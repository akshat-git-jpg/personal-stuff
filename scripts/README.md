# scripts

Repo-wide orchestration scripts in one place, plus an index of everything *outside* this repo that depends on its layout. If you move or rename a folder, this is the list of things that break.

## Scripts here

- `relink.sh` — machine-local skill setup. Skills themselves are repo-scoped and need no linking; this handles the three edges: the Codex mirror, the push-gate install, and the shared memory store. Idempotent. Run it after cloning, after moving the repo, or after changing skill membership. Resolves the skill store relative to itself, so a repo rename doesn't break it — but the symlinks it already created point at absolute paths, so you must re-run it after a move.
- `link-clis.sh` — the CLI counterpart to `relink.sh`: symlinks this repo's own PATH-facing CLIs (`wt`, `yt-claude`) into `~/.local/bin` from an explicit list at the top of the script. Idempotent and self-healing — repairs stale links, never clobbers real (non-symlink) files, never touches names it doesn't manage. Run it after cloning or moving the repo; add a new repo CLI by appending one line to the list.
- `regen-mcp-json.sh` — rewrites the gitignored `.mcp.json` at the repo root with this machine's `tooling/mcp` server paths. Run after cloning or moving the repo.
- `vps-sync.sh` — **VPS only.** `git pull`s the VPS clone and installs the push gate. It no longer links skills: a VPS session running inside the checkout reads `.claude/skills` directly. The VPS counterpart to `relink.sh`. A `repo-sync` cron runs it every 15 min so interactive Claude (Remote Control / mobile) on the VPS stays current with what you push. Safe to run by hand for an instant sync.
- `node22-path.sh` — **source it, don't run it.** Puts Node >=22 on `PATH` for the current shell, because wrangler >=4 hard-refuses Node < 22 while this Mac's default is deliberately Node 20 (the owner's Zluri work repos need 20; nothing in this repo does). No-op when node is already >=22, idempotent, and exits 1 with a `brew install node@22` hint when it can't find one. Already wired into `deploy-apps.sh`, `tooling/boss/bin/boss-deploy.sh`, and every `apps/*` npm script that invokes `wrangler`, `vite`, `vitest`, `tsc`, `tsx` or `playwright` (11 apps), always as the FIRST thing in the script body so it also covers a nested `npm install`. Only wrangler 4 hard-fails on Node 20 (6 of 10 Worker apps); the rest is future-proofing — vite 8 wants `node ^20.19 || >=22.12` and this Mac is on 20.18.3, which only warns. Call it from anything new that shells out to a node toolchain.
- `check-apps.sh` — Uniform verification runner. Iterates through all apps and runs typecheck/check, lint, and test scripts. Returns exit code 0 if all pass, 1 if any fails.
- `deploy-apps.sh` — check-apps-gated deploy loop: runs each app's own `deploy` script (apps own their quirks, e.g. patch-routes). `--only a,b`, `--dry-run`, `--skip-checks`. DEPLOYS TO PROD — dry-run first.
- `skills-status.sh` — read-only: where skills load (repo, Codex mirror, private plugin), plus any stale account symlink left over from the old global store; exit 1 on a dangling/missing/unresolved link. Run it when a skill seems absent or after moving the repo (then fix with relink.sh).
- `probe-sites.sh` — parses my-hosted-sites.md and curls every public URL; exit 1 + DOWN_SITES: line if any site is unreachable/5xx. Run by the site-probe VPS cron hourly; safe to run by hand.

## External touchpoints (things that hardcode this repo's path)

These live outside the repo and must be updated by hand if the repo moves or a folder is regrouped:

- **pipelines/ workspace rename** — `pipelines/` was formerly `ty/`. Any external script, shell alias, launchd daemon, or cron wrapper hardcoding `/ty/` must be updated by hand (including VPS directories or Traefik compose mappings).
- `~/.zshrc` — a git-identity rule mapping this repo path to the `akshat-git-jpg` GitHub account, and the `ccu-dash` alias pointing at `tooling/cli/ccusage-dashboard/dashboard.mjs`.
- `~/.codex/skills/` — symlinks into `.claude/skills/` for the names in `.claude/codex-skills.txt` (regenerated by `relink.sh`). Codex has no per-repo skill path.
- `~/codebase/work-skills/` — the private plugin; `sync-shared-skills.sh` keeps its copy of five person-level skills identical to this repo's.
- `.mcp.json` (repo root, gitignored) — absolute paths into `tooling/mcp` (regenerated by `regen-mcp-json.sh`).
- The `github-router` skill (`.claude/skills/github-router/SKILL.md`) — its path → account rule keys on this repo's path.
- The separate `vps-crons` repo (`~/codebase/vps-crons`) — its `my-planner/run.sh` and `gmail-digest/run.sh` wrappers reference `apps/telegram-my-planner/tools/daily-digest/` and `apps/telegram-email-assistant/digest.sh` inside the VPS clone of this repo.
- The Hostinger VPS — clones this repo to `/srv/projects/personal-stuff/` and `vps-crons` to `/srv/crons/`. Both pull on cron ticks. Gitignored runtime (`.venv`, `token.json`) does not move with `git pull`, so relocate it on the VPS after any folder regroup.

## After cloning on a new machine

```bash
./scripts/relink.sh          # recreate skill symlinks
./scripts/link-clis.sh       # put the repo's own CLIs (wt, yt-claude) on PATH
./scripts/regen-mcp-json.sh  # write .mcp.json for this machine
```
