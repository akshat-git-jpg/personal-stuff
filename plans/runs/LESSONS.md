# Cross-run executor lessons

Append-only, one line per non-obvious lesson learned from a run — recurring
executor mistakes, plan-shape fixes that prevented them, quirks. The
orchestrator reads this during recon (orchestrate Step 2) and writes to it
after verification (Step 4d), so every batch compounds instead of
rediscovering failure modes through fix-up rounds.

Format: `YYYY-MM-DD <executor> — <lesson>`

2026-08-23 orchestrate/claude-p — plan 234's hosted Cloudflare mode shipped with THREE separate bugs that each made every freelancer link dead, and all three passed `test_cmd`, both screenshots and the `ui: true` gate. (1) The Worker served the `/d/:token` shell by fetching `/index.html`; the assets binding's default `html_handling` answers that with a 307 to `/`, stripping the token before the SPA boots. (2) `App.tsx` derived its video key from `?key=` alone and returned the "no ?key= in the URL" screen before any fetch — `api.ts` had resolved hosted mode correctly, so the API, the Worker and the DB were all right and the page was still an error. (3) A dead token rendered the full chrome ("Beats 1-0", tabs, toggles) plus an error line, reading as a script that loaded empty. Root cause is one thing: **every test exercised local mode (`?key=`), and nothing ever ran the hosted path.** A dual-mode surface needs its second mode tested explicitly — for a token-in-the-path SPA that means rendering `<App/>` with `window.location.pathname` set to `/d/<token>` and asserting the error screen is ABSENT, not just that the API returns 200. This repeats 2026-07-23 verbatim ("Pure-logic vitest cannot catch routing bugs — smoke the deployed routes before declaring a Worker done"), so the curl smoke is not enough either: curl said 200 on all three broken versions because the shell HTML always loads. **Open the deployed URL in a headless browser and assert on rendered text** before calling a hosted app done.
